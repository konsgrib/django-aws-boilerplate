## How to Get the Password

Run this command to retrieve the superuser password:

```bash
aws secretsmanager get-secret-value \
  --secret-id autoakademia/dev/django/superuser \
  --query SecretString \
  --output text | jq -r '.password'
```

For production environment, replace `dev` with `prod`:

```bash
aws secretsmanager get-secret-value \
  --secret-id autoakademia/prod/django/superuser \
  --query SecretString \
  --output text | jq -r '.password'
```

## Change Password

### Method 1: Via AWS Secrets Manager (Recommended)

Update the password in AWS Secrets Manager and apply it to the database:

```bash
# Set new password (use alphanumeric only to avoid login issues)
NEW_PASSWORD="YourNewPassword123"

# Update secret in AWS
aws secretsmanager update-secret \
  --secret-id autoakademia/dev/django/superuser \
  --secret-string "{\"username\":\"admin\",\"email\":\"admin@autoakademia.com\",\"password\":\"$NEW_PASSWORD\"}"

# SSH to EC2 and apply the new password
ssh -i autoakademia.pem ec2-user@<EC2_IP>
cd /home/ec2-user/autoakademia

# Update .env
SUPERUSER_JSON=$(aws secretsmanager get-secret-value --secret-id autoakademia/dev/django/superuser --query SecretString --output text)
SUPERUSER_PASSWORD=$(echo "$SUPERUSER_JSON" | jq -r '.password')
sed -i "s/^DJANGO_SUPERUSER_PASSWORD=.*/DJANGO_SUPERUSER_PASSWORD=${SUPERUSER_PASSWORD}/" .env

# Update password in Django database
docker compose exec -T django python manage.py shell <<PYEOF
from django.contrib.auth import get_user_model
User = get_user_model()
user = User.objects.get(username='admin')
user.set_password('$NEW_PASSWORD')
user.save()
print('Password updated successfully')
PYEOF
```

### Method 2: Via Django Management Command

Use Django's built-in command to change password interactively:

```bash
ssh -i autoakademia.pem ec2-user@<EC2_IP>
cd /home/ec2-user/autoakademia
docker compose exec django python manage.py changepassword admin
```

**Important:** After changing password via Django command, also update AWS Secrets Manager to keep them in sync.

## Troubleshooting

### "Please enter the correct username and password" Error

If you see this error despite using correct credentials:

1. **Special Characters Issue**: Auto-generated passwords with special characters (`+`, `)`, `:`, `^`, etc.) can cause login issues in some browsers or Django versions.

   **Solution**: Update password to use only alphanumeric characters:
   ```bash
   aws secretsmanager update-secret \
     --secret-id autoakademia/dev/django/superuser \
     --secret-string '{"username":"admin","email":"admin@autoakademia.com","password":"NewSimplePassword123"}'
   ```
   
   Then update in database (see "Change Password" section above).

2. **Browser/Cookie Issues**: Clear browser cookies and cache, or try incognito mode.

3. **Case Sensitivity**: Ensure username and password are entered exactly as stored (case-sensitive).

4. **User Not Active**: Verify user is active in database:
   ```bash
   docker compose exec django python manage.py shell -c \
     "from django.contrib.auth import get_user_model; User = get_user_model(); \
     u = User.objects.get(username='admin'); \
     print(f'Active: {u.is_active}, Staff: {u.is_staff}, Superuser: {u.is_superuser}')"
   ```

### Password Not Syncing

If password in AWS Secrets doesn't match database:

1. Verify EC2 IAM role has permissions to read the superuser secret
2. Check `.env` file on EC2 has correct password: `cat /home/ec2-user/autoakademia/.env | grep SUPERUSER_PASSWORD`
3. Manually sync password using script in "Change Password" section

## Password Policy

All secrets (Django SECRET_KEY, Database password, Superuser password) are automatically generated by AWS Secrets Manager with the following rules:

**Excluded Characters:** `"@/\<>%` ` |&;$` and punctuation

These characters are excluded to prevent:
- URL encoding issues in database connection strings
- Shell script escaping problems in docker-compose and bash scripts
- Django admin login failures due to browser/form encoding
- PostgreSQL authentication errors with special characters

**Password Specifications:**
- **Django SECRET_KEY**: 64 characters, alphanumeric only
- **Database Password**: 32 characters, alphanumeric only  
- **Superuser Password**: 16 characters, alphanumeric only

## Security Notes

- All passwords are randomly generated on CloudFormation stack creation
- Passwords are stored in AWS Secrets Manager with encryption at rest
- Never commit passwords to git or store in plaintext
- Use IAM policies to restrict access to Secrets Manager
- Consider rotating passwords periodically for production environments
- For production, change default superuser password immediately after first login
- EC2 instance has IAM role permissions to read secrets (no hardcoded credentials)
